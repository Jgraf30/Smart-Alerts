# Smart Alerts — Data Model

Two SharePoint lists (or Dataverse tables) power the solution.

---

## List 1: AlertSubscriptions

Stores each user's alert preferences. One row per subscription.

| Column | Type | Description |
|---|---|---|
| Title | Single line | Friendly name for this subscription (e.g. "Project Register Changes") |
| SubscriberEmail | Single line | Email address of the person receiving alerts |
| SubscriberName | Single line | Display name |
| SiteURL | Single line | Full URL of the SharePoint site being monitored |
| ListOrLibraryID | Single line | GUID of the list or library to monitor |
| ListOrLibraryName | Single line | Human-readable name (for display in the app) |
| MonitorType | Choice | List Item \| Document Library |
| DeliveryMethod | Choice | Email \| Teams \| Both |
| TeamsChannelID | Single line | Teams channel webhook URL (if Teams delivery selected) |
| TriggerCondition | Choice | Any Change \| Specific Columns \| Keyword Match |
| WatchedColumns | Multiple lines | Comma-separated column names to watch (if Specific Columns selected) |
| Keywords | Multiple lines | Comma-separated keywords that trigger an alert (if Keyword Match selected) |
| IsActive | Yes/No | Whether this subscription is currently active |
| CreatedDate | Date | When the subscription was created |
| LastModified | Date | When the subscription was last updated |

---

## List 2: AlertLog

Stores a record of every alert sent. Used for audit, review, and the history view in the Power App.

| Column | Type | Description |
|---|---|---|
| Title | Single line | Auto-generated: "[List Name] — [Item Title] changed" |
| SubscriptionID | Lookup | Links to the AlertSubscriptions list |
| SubscriberEmail | Single line | Who received the alert |
| SiteURL | Single line | Site where the change occurred |
| ListOrLibraryName | Single line | List or library that changed |
| ItemID | Number | SharePoint item ID that changed |
| ItemTitle | Single line | Title of the changed item |
| ChangedBy | Single line | Display name of user who made the change |
| ChangedByEmail | Single line | Email of user who made the change |
| ChangeTimestamp | Date/Time | When the change occurred |
| ChangeType | Choice | Created \| Modified \| Deleted |
| ChangedFields | Multiple lines | Which fields changed (JSON) |
| BeforeValues | Multiple lines | Values before the change (JSON) |
| AfterValues | Multiple lines | Values after the change (JSON) |
| AISummary | Multiple lines | The plain-English summary generated by Copilot Studio |
| DeliveryStatus | Choice | Sent \| Failed \| Partial |
| DeliveryMethod | Choice | Email \| Teams \| Both |
| ErrorDetails | Multiple lines | Error message if delivery failed |

---

## Notes

- If using **Dataverse** instead of SharePoint lists, column types map directly to Dataverse equivalents
- The `ChangedFields`, `BeforeValues`, and `AfterValues` columns store JSON — parse these in Power Automate before passing to Copilot Studio
- Index the `SubscriberEmail` and `IsActive` columns in AlertSubscriptions for faster lookup during flow execution
- The AlertLog list will grow over time — consider a retention policy to archive entries older than 90 days
